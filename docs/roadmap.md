# BetterLearn for DSH 路线图

本路线图只描述独立 DSH 插件主线，不继承旧 Nobei 的企业产品化批次或 Claude Code sidecar 方案。

## P0：独立仓库收口（已完成）

- 独立构建、测试与 tarball 验证通过；
- 固定 DSH rc.7 依赖与基础迁移来源；
- 默认验证不依赖旧仓库、旧数据库和历史 evidence。

## P1：状态同步闭环（已完成）

- Core 生成完成后 WebUI 自动进入审核界面；
- 短轮询作为同步机制：1→2→4→8 秒退避，有新事件即重置回 1 秒；
- 失败、重试和恢复的基础文案已具备。

## P1.1：可选体验优化

- SSE 即时推送：把「生成完成 → 进入审核」从最坏约 8 秒延迟缩短为即时；
- 轮询兜底保留（现有 pollRun 已经是兜底）；
- 失败、重试和恢复文案统一审计。
- 是否引入取决于真实使用中 1–8 秒延迟是否明显影响体验，非当前必做项。

## P2：独立产品数据模型

- 确定 BetterLearn 作为独立产品自己的数据模型（文档、知识点、证据、审核状态、任务与 attempt）；
- 不再背负旧 Nobei 数据模型合并的决策；
- 明确当前 p1_* 控制表与产品领域表之间的关系和演进方向。

设计稿见 [数据模型设计](data-model.md)。

## P3：能力扩展

- PDF 与结构化解析；
- 长文档分块和 L2/L3 路由；
- 多证据知识点与文档级绝对坐标；
- 基于真实分布改进重复 quote 的消歧体验。

## P4：交付

- 普通用户的安装、启动、升级与卸载流程；
- 数据备份和恢复演练；
- DSH rc.8 独立升级演练；
- 稳定版本发布前的产品体验与错误提示收口。
