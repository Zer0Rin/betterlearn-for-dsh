# BetterLearn 全局提取历史设计

**日期：** 2026-09-01  
**状态：** 已完成对话设计确认，等待书面规格确认

## 背景

BetterLearn Core 已经把每次材料导入、生成、人工审查和知识点结果保存在全局 SQLite 数据库中，但客户端目前只在每个 DSH 会话对应的 `sessionStorage` 项中记录一个 `runId`。创建新任务后，这个指针会被新 `runId` 覆盖，旧任务虽然仍在数据库里，界面却没有入口可以再次打开。

本次升级为右侧悬浮工作台增加类似 Codex / ChatGPT 的可收缩历史侧栏，让用户能够查看和切换全部 BetterLearn 提取任务，同时保留刚刚验收的小窗尺寸和现有业务流程。

## 目标

- 从 BetterLearn 全局 SQLite 中读取全部提取任务，而不是从 DSH 会话或浏览器存储拼接历史；
- 历史侧栏默认收起，打开 BetterLearn 时仍保持当前已验收的小窗宽度；
- 展开历史侧栏时，悬浮工作台整体向左增宽，当前业务内容不被压缩；
- 支持从历史中重新打开处理中、待审查、已完成和失败任务；
- 创建新的提取任务后，旧任务继续留在历史列表中；
- 查看历史记录不触发新的模型调用，不产生提取费用；
- 为以后“从 DSH 对话历史提取学习内容”保留清晰的来源表达方式，但本次不实现对话导入。

## 非目标

- 不实现删除、搜索、分类、置顶或重命名；
- 不实现分页或虚拟列表，首版一次返回全部任务摘要；
- 不引入向量数据库、向量索引或全文检索；
- 不修改现有材料正文、候选知识点、人工审查和正式知识点的持久化模型；
- 不实现从 DSH 数据库读取对话消息；
- 不重新运行历史任务，也不因为打开历史而调用模型。

## 产品行为

### 默认状态

- 页面加载后 BetterLearn 仍默认收起为右侧启动按钮；
- 点击 BetterLearn 后打开当前尺寸的工作台；
- 历史侧栏默认收起，只显示一个明确的历史入口；
- 历史侧栏的展开状态是页面级临时 UI 状态，刷新后恢复为收起。

### 展开历史

- 点击历史入口后，侧栏从主内容左侧出现；
- 悬浮面板保持右边界不变，整体向左增宽；
- 主内容区域继续使用当前 screen 对应的宽度，不因侧栏出现而缩窄；
- 再次点击历史入口或侧栏收起按钮，面板恢复当前 screen 的既有宽度；
- 移动端沿用悬浮工作台现有全屏规则，历史和内容在全屏范围内布局，不突破视口。

### 历史列表

历史是 BetterLearn 全局列表，与当前 DSH 会话无关。切换 DSH 会话时：

- 历史条目集合和排序保持一致；
- 当前 DSH 会话仍可通过原有 `sessionStorage` 键记住最后查看的 `runId`；
- `sessionStorage` 只是当前视图指针，不再被当作历史数据源。

列表按 `updatedAt` 从新到旧排列。每条显示：

- 材料名称；
- 面向用户的状态；
- 最近更新时间；
- 候选知识点数量；
- 已形成的正式知识点数量。

列表顶部提供“新建提取”操作。点击后只把当前工作区切回导入界面，不删除、隐藏或覆盖任何历史任务。

### 打开历史任务

- 点击条目后，将该 `runId` 写为当前 DSH 会话正在查看的任务；
- 停止客户端对上一任务的轮询和界面请求，随后加载所选任务；
- Core 中已经开始的生成不依赖浏览器轮询，切走后仍继续执行；
- 根据任务真实状态复用现有 `RunProgress`、`ReviewWorkspace` 或 `ResultSummary`；
- 切回旧任务时只读取已保存数据，不重新导入、不重做生成、不调用模型；
- 点击处理中条目时，以 `runs.get` 的最新快照恢复轮询；
- 点击待审查或已完成条目时，继续使用现有候选和知识点读取接口。

## 状态展示

Core 的原始状态保持不变，历史侧栏只做显示映射：

| Core 状态 | 历史显示 |
| --- | --- |
| `created`、`document_ready`、`awaiting_generation`、`generating`、`validating` | 处理中 |
| `review_pending` | 待审查 |
| `completed` | 已完成 |
| `failed_retryable`、`failed_terminal` | 失败 |

失败任务打开后继续复用现有失败详情和重试能力；历史侧栏不新增另一套重试交互。

## 数据契约

### Core RPC

新增只读方法 `runs.list`，参数必须是空对象，返回闭合结果：

```ts
interface RunHistoryResult {
  runs: RunHistorySummary[]
}

interface RunHistorySummary {
  runId: string
  sourceType: 'document'
  sourceLabel: string
  status: RunStatus
  stage: RunStage
  updatedAt: string
  candidateCount: number
  knowledgePointCount: number
}
```

当前版本中：

- `sourceType` 固定为 `document`；
- `sourceLabel` 来自 `documents.filename`；
- `candidateCount` 来自该任务的有效候选数量；
- `knowledgePointCount` 来自该任务已接受并形成的正式知识点数量。

`sourceType` 和 `sourceLabel` 是新历史摘要契约的一部分，不要求本次修改数据库 Schema。未来接入 DSH 对话时，可以增加新的来源类型和来源关联，而历史侧栏仍通过相同的来源标签渲染条目。

### SQLite 查询

Core 在一个只读快照中联结 `runs` 与 `documents`，只选择历史摘要所需字段，不返回材料正文、候选内容或证据。排序规则为：

```sql
ORDER BY runs.updated_at DESC, runs.created_at DESC, runs.id DESC
```

首版不传分页参数，也不设置产品级条数截断。

### Host API

新增：

```text
GET /nobei/v1/runs
```

Host 将该请求转发到 Core 的 `runs.list`，成功时继续使用既有产品响应包装：

```json
{
  "ok": true,
  "result": {
    "runs": []
  }
}
```

该接口只读取本地 SQLite，不接触模型提供商。

### Client API

`ClientApi` 新增：

```ts
listRuns(signal?: AbortSignal): Promise<RunHistoryResult>
```

客户端通过 `GET /nobei/v1/runs` 获取全局摘要。`sessionStorage` 中既有每会话状态格式保持不变，只继续保存当前 `runId`、事件游标和未完成审查命令。

## 客户端结构

### `HistorySidebar`

新增单一历史侧栏组件，负责：

- 加载态、空状态、错误与重试；
- 渲染全局任务摘要；
- 标记当前查看的 `runId`；
- 触发选择任务和新建提取；
- 把 Core 原始状态映射为中文状态标签。

历史请求失败时，只在侧栏中显示失败信息和重试按钮，不替换或破坏当前工作区内容。

### `NobeiWorkspace`

继续复用现有四个业务 screen，并增加历史布局和任务切换协调：

- 维护历史侧栏是否展开；
- 把侧栏展开状态报告给悬浮 Shell；
- 将历史选择交给 `useNobeiWorkspace.openRun(runId)`；
- 将“新建提取”交给现有 reset/import 语义；
- 成功创建新任务后刷新历史并选中新任务；
- 主动打开侧栏时重新读取历史；
- 当前任务在导入、重试、状态完成或人工审查后发生变化时刷新历史摘要。

不为后台所有任务新增持续轮询。用户重新展开侧栏或点击某条历史时，会读取最新数据；这样能够看到后台已完成的状态，同时保持实现简单。

### `useNobeiWorkspace`

新增显式的 `openRun(runId)` 能力：

1. 中止上一任务的客户端轮询和未完成读取；
2. 清理只属于上一任务的进度、事件、候选、知识点和选中候选状态；
3. 将新 `runId` 写入当前 DSH 会话的 `sessionStorage`；
4. 从事件游标 `0` 加载该任务，以数据库快照为准恢复正确 screen；
5. 保持 Core 后台生成生命周期不受客户端切换影响。

`reset()` 只清除当前会话的查看指针并回到导入 screen，不删除数据库中的任务。

### `BetterLearnFloatingApp`

- 继续控制整个工作台的展开和收起；
- 接收历史侧栏展开状态，并在面板上输出对应布局状态；
- 历史收起时完全沿用现有 screen 宽度；
- 历史展开时在既有宽度基础上增加侧栏宽度，并保持向左扩展；
- BetterLearn 整体收起后，历史侧栏状态重置；下次展开仍默认收起。

## 历史刷新时机

历史摘要在以下时机重新获取：

1. 本次页面生命周期中第一次展开历史侧栏；
2. 后续每次从收起切换为展开；
3. 成功创建新提取任务后；
4. 当前任务重试、进入待审查、完成人工审查或进入失败状态后；
5. 用户在侧栏错误状态点击重试时。

历史侧栏保持展开时，不额外轮询整个列表。点击任一条目仍会通过任务详情接口取得该任务的真实最新状态。

## 未来 DSH 对话来源

未来的对话提取作为独立输入适配器实现，不让历史功能直接读取或解释 DSH 数据库：

```text
选择 DSH 会话
    ↓
读取并规范化对话消息
    ↓
创建 BetterLearn 来源记录与规范文本
    ↓
进入现有生成、审查、知识点流程
    ↓
通过同一全局历史列表展示
```

本次只在历史摘要中建立 `sourceType` / `sourceLabel` 的显示边界。对话消息表结构、同步策略、增量提取和来源 Schema 留给后续独立设计。

## 错误处理

- `runs.list` 失败：侧栏显示加载失败和重试，当前任务界面保持可用；
- 某条历史在选择时无法读取：沿用当前产品 API 错误提示，刷新历史列表，不自动创建替代任务；
- Core 暂时不可用：历史和当前工作区分别显示各自现有的不可用状态，恢复后可手动重试；
- 请求被任务切换中止：不显示错误；
- 空数据库：显示“还没有提取记录”和“新建提取”入口。

## 测试策略

按照测试先行覆盖以下层次：

### Python Core

- `runs.list` 返回所有任务，并按更新时间倒序；
- 同一秒更新时间使用次级排序得到稳定顺序；
- 摘要字段闭合，不泄露正文、证据、模型元数据或内部错误详情；
- 所有 Core 状态都能返回；
- 候选和正式知识点数量正确；
- 空数据库返回空数组。

### RPC 与 Host

- RPC 公开方法表包含 `runs.list`，只接受空参数；
- Core RPC Client 正确发送并读取历史摘要；
- `GET /nobei/v1/runs` 返回 `200` 和标准产品包装；
- 其他方法、路径、查询参数和请求体继续遵守现有路由规则；
- Core 不可用时返回既有 `503 CORE_UNAVAILABLE`。

### Client

- Client API 调用正确路径并支持中止；
- 历史侧栏默认收起，展开时请求全局历史；
- 列表显示材料名、状态、时间和数量并标记当前任务；
- 切换任务会中止旧轮询、更新当前 `runId` 并恢复正确 screen；
- 新建提取不会从历史中移除旧任务；
- 历史错误不会替换当前工作区；
- 切换 DSH 会话时历史数据源不变；
- 历史展开使悬浮窗向左增宽，主内容宽度不变；收起后恢复 screen 原宽度。

## 完成标准

- 用户能够从 BetterLearn 内看到数据库中已有和新建的全部提取任务；
- 连续提取新材料不会让旧任务失去界面入口；
- 任意历史任务都能恢复到与其状态匹配的现有业务界面；
- 历史列表不随 DSH 会话切换而丢失；
- 历史默认收起，展开不压缩主内容，关闭后恢复当前小窗尺寸；
- 浏览历史不产生模型调用；
- 当前数据库无需迁移；
- 自动测试和零费用浏览器验收通过。
