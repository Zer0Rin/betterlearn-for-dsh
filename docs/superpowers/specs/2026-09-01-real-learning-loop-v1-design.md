# BetterLearn 真实学习闭环 V1 设计

日期：2026-09-01
状态：继承已确认的《个性化学习空间设计》，进入实现

## 1. 本轮要解决的问题

当前学习空间只是 UI 纵切预览：所有知识点复用同一道“哪一种学习方式更可靠”的固定题，答案只保存在 React 内存，掌握度固定为 0，关闭后丢失。用户无法判断学习书是否真的围绕所选内容教学。

本轮只完成已确认总体设计中的一个窄闭环：

1. 学习书第一次打开时，在 Python Core 中冻结所选正式知识点及证据；
2. Core 根据整本书的真实陈述和真实引文编译“陈述辨析 + 证据定位”两类客观题；
3. 学习者只获取公开题面和选项，正确答案仅保存在 Core；
4. 真实作答原子写入 SQLite，由 Core 判分；
5. 答错后进入定向补救和证据复测；
6. 掌握度、完成状态和下一次复习时间持久化；
7. 学习空间与书架展示真实进度，不再出现“交互预览 / 数据不会保存”。

问卷、诊断、模型生成路径、开放题 rubric judge 和模型生成教学包继续按总体设计分批实现，不在本轮伪造。

## 2. 参考源码后的取舍

参考 `better-learn-cc` 的 DeepTutor 源码与拆解，本轮复用：

- Mastery 的私有答案登记、真实作答、确定性判分与补救复测交易；
- Reading 的“知识陈述必须对应原文引文”边界；
- Spaced Repetition 的程序化复习时间，而不是只在文案中声称已掌握。

本轮不复制：

- 同一个模型同时生成题目、答案和解释；
- 浏览器直接持有答案并自行判分；
- 只靠提示词维持的教学门槛；
- 开放题由同一导师模型自评的布尔结果。

## 3. 方案比较

### 方案 A：只替换前端文案

最快，但仍然是内存预览，刷新即丢失，浏览器持有答案，不能称为真实学习闭环。

### 方案 B：前端 localStorage 保存答题

能够恢复进度，但私有答案仍在前端，Client 自行决定掌握，违反已经确认的 Core 事实源边界。

### 方案 C：Core 持久化的内容相关客观题闭环（采用）

工作量更大，但与现有架构一致：Core 冻结素材、保存私有答案、判分并更新掌握；Host 只传输；Client 只展示 learner-safe DTO。该方案直接修复当前可见问题，又不给未来的模型生成路径制造第二套状态。

## 4. 数据模型

数据库从版本 1 原地迁移到版本 2，保留所有现有提取数据。

- `learning_courses`：课程 ID、浏览器学习书 ID、标题、状态、创建/更新时间；
- `learning_units`：课程内顺序、冻结的知识点类型/标题/陈述/证据 JSON；不依赖原知识点继续存在；
- `learning_assessments`：公开题面/选项、私有正确选项、题型、补救说明；
- `learning_attempts`：幂等键、真实选项、判分结果、时间；
- `learning_mastery_states`：单元状态、掌握强度、主测/复测次数、最近结果、下一次复习时间。

课程同步以 `clientBookId` 幂等。同一个学习书 ID 再次打开时必须与首次冻结的标题和知识点顺序一致，否则返回冲突，不能静默替换课程。

## 5. 题目编译

每个知识点形成一个单元：

- 核心讲解：使用人工确认后的正式陈述；
- 证据练习：展示冻结的精确原文引文及其上下文；
- 主测（`claim_choice`）：题目询问哪项准确描述当前知识点。正确项为当前正式陈述，干扰项优先取同一学习书其他知识点的正式陈述；
- 复测（`evidence_choice`）：题目询问哪段原文直接支持当前陈述。正确项为当前冻结证据，干扰项优先取同书其他知识点的真实引文。

选项顺序由稳定摘要确定，避免正确答案总在同一位置。单知识点学习书没有同书干扰项时，使用明确标记的否定性回退选项；不编造新的知识事实。

## 6. 作答与掌握状态机

```text
new
  ├─ 主测正确 → mastered (100, 3 天后复习)
  └─ 主测错误 → remediation_required (20, 立即补救)
       ├─ 复测正确 → mastered_after_remediation (70, 1 天后复习)
       └─ 复测错误 → learning (20, 立即可重试)
```

每次提交必须有 `idem_` 幂等键。相同键和相同请求返回首次结果；相同键对应不同请求返回冲突。Core 在同一事务中写作答和掌握状态。

课程进度由 mastery 状态投影：`mastered` 与 `mastered_after_remediation` 计入完成；总体掌握度是各单元强度的平均值。

## 7. API 与边界

- `POST /nobei/v1/learning-courses`：传入学习书 ID、标题和有序知识点 ID；创建或读取冻结课程；
- `GET /nobei/v1/learning-courses/:courseId`：读取 learner-safe 课程快照；
- `POST /nobei/v1/learning-assessments/:assessmentId/attempts`：提交客观题答案并返回判分后的课程快照。

公开快照不包含 `correct_option_id`。Host 的路由、TS 类型和 Core RPC 都执行严格输入校验。

## 8. UI 结果

- 打开学习书时显示真实加载态；
- 题目与当前知识点内容直接相关；
- 答错后显示当前陈述和对应引文的定向补救；
- 提交后进度、掌握度、单元状态和复习时间立即更新；
- 返回书架后显示“已完成 x/y · 掌握度 n%”或“尚未开始”；
- 刷新或重启真实 DSH 后从 Core 恢复。
