# 学习书管理设计

## 目标

让“学习空间”同时承担学习书入口和管理入口。用户可以修改或删除学习书，同时避免误操作和已有学习进度被静默覆盖。

## 已确认规则

- 书架采用独立的“管理模式”。默认仍是学习入口；点击“管理”后，每本书显示“修改”和“删除”，点击书本不再进入学习。点击“完成”退出管理模式。
- 未开始学习的书可原地修改名称、知识点顺序和知识点集合。
- 已开始学习的书修改后保存为新版本。原书、原课程和原学习进度保持不变，新版本从未开始状态进入书架。
- 删除需要二次确认。确认后同时删除学习书、课程、答题记录和掌握度。

## 界面与组件

### 学习书架

`LearningBookshelf` 增加内部管理模式状态，并通过回调把修改和删除意图交给工作台处理。

- 普通模式：书卡保持“开始学习 / 继续学习”行为。
- 管理模式：书卡展示“修改”和“删除”；操作按钮不会触发打开学习书。
- 删除确认：在当前书卡内展示明确的删除范围，以及“取消”和“确认删除”，避免浏览器原生弹窗脱离界面语境。
- 删除处理中禁用重复操作；失败后恢复按钮并展示错误，不移除书卡。

### 学习书编辑器

复用 `LearningBookComposer`，增加创建与编辑两种语义：

- 创建时沿用默认书名，主操作为“创建学习书”。
- 编辑时使用现有书名和知识点顺序，主操作为“保存修改”或“保存为新版本”。
- 编辑未开始书保存后替换原记录，并保留书架位置。
- 编辑已开始书保存后创建新的 `bookId` 和创建时间，插入书架首位；原书不变。
- 至少保留一个知识点，书名去除首尾空白后不能为空。

## 数据流

### 修改

工作台保存正在编辑的学习书及原始正文。编辑器只返回名称和排序后的知识点：

1. 若原书没有 `courseId` 和学习进度，生成更新后的本地学习书并原位替换。
2. 若原书已经绑定课程或学习进度，生成全新的学习书，不复制 `courseId` 或 `progress`。
3. 本地持久化成功后返回书架；持久化失败时保留本次内存状态并显示现有存储警告。

### 删除

产品核心新增按课程 ID 删除学习课程的写接口。数据库外键级联清理学习单元、题目、答题记录和掌握度：

1. 未开始且没有 `courseId` 的学习书在确认后只需从本地书架删除。
2. 已绑定课程的学习书先请求产品核心删除课程。
3. 核心成功后再删除本地学习书并持久化，确保后端失败时用户仍能看到并重试。
4. 删除接口采用幂等语义：课程已不存在时也视为删除成功，便于失败重试后收敛状态。

## 错误处理

- 核心删除失败：保留学习书和全部本地数据，在书架显示可重试错误。
- 本地持久化失败：沿用当前警告机制，明确说明关闭页面后修改或删除可能无法保留。
- 删除进行中：禁止再次修改、删除或打开同一本书。
- 删除新版本不会影响旧版本；删除旧版本也不会影响由它编辑产生的新版本。

## 测试与验收

- 组件测试：管理模式切换、按钮事件隔离、编辑初始值、未开始书保存、已开始书另存新版本、删除确认与取消、删除失败保留书卡。
- 数据测试：学习书更新不会篡改输入；新版本不继承课程与进度；本地存储往返一致。
- 产品核心测试：删除课程会级联删除单元、题目、答题记录和掌握度；重复删除成功；非法课程 ID 被拒绝。
- 路由与客户端测试：删除 RPC/HTTP 映射、无请求体约束、错误传播。
- 回归测试：完整测试套件、构建与打包通过。
- 实际验收：升级 `http://127.0.0.1:3000/` 的运行版本，检查管理模式、编辑流程和删除确认；不实际删除用户现有学习书。

## 范围边界

本次不增加批量删除、跨书合并、撤销删除、归档、版本树或云同步。新版本与原书仅通过标题和创建时间区分，不引入额外版本关系字段。
