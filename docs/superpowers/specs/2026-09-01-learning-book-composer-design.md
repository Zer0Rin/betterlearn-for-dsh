# BetterLearn 学习书整理流程设计

## 目标

修正学习空间的两处导航与创建问题：课程退出按钮使用明确的“返回”，并固定回到学习书架；知识点不再一键覆盖现有学习书，而是先进入独立整理页，再创建一本新的学习书。

## 用户流程

```text
BetterLearn 首页
  → 知识点
  → 选择正式知识点
  → 整理学习书
  → 创建学习书
  → 学习书架（新书置顶）
  → 点击学习书
  → 具体学习
  → 返回
  → 学习书架
```

“整理学习书”是普通尺寸下的独立页面，不与知识点结果页内联，也不使用叠加弹窗。

## 整理页

整理页提供：

- 自动生成且可编辑的书名；
- 已选正式知识点及总数；
- 每个知识点的上移、下移与移除操作；
- 最终学习顺序预览；
- “取消整理”和“创建学习书”操作。

书名为空或知识点为空时禁止创建。取消整理返回知识点结果页，不产生学习书。

## 创建规则

每次确认都创建一本新书。即使知识点集合与顺序完全相同，也不得替换已有学习书。

每本学习书包含：

- 独立且稳定的 `bookId`；
- 用户确认的书名；
- 创建时间；
- 来源正文；
- 按用户顺序保存的正式知识点；
- 由这些知识点生成的课程单元。

创建成功后返回学习书架，新书排在第一位并显示“刚刚创建”。不会自动进入具体学习，用户必须点击学习书。

## 组件边界

### `LearningBookComposer`

只负责编辑学习书草稿。输入为知识点与来源正文，输出为已命名、已排序的创建请求；不负责保存，也不直接打开课程。

### `LearningBookshelf`

只展示已保存学习书并发出打开事件。创建后的高亮由 `bookId` 标识，不推断知识点是否相同。

### `learning-library-storage`

使用版本化浏览器本地存储读写学习书。解析时严格验证数据；损坏或未知版本数据按空书架处理。写入失败时保留当前运行内的新书，并向界面返回非阻断提示。

### 悬浮窗状态

普通尺寸区域扩展为：

```text
home | knowledge | compose | library
```

具体课程继续使用扩展尺寸的 `learning` 模式。合法转换为：

```text
knowledge → compose
compose → knowledge（取消）
compose → library（创建）
library → learning（打开学习书）
learning → library（返回）
```

## 本地保存

当前阶段使用版本化 `localStorage` 保存学习书，使其在收起、重新打开或刷新后仍然存在。该存储是本阶段的用户体验实现，不代替后续 SQLite 正式领域模型。

## 错误处理

- 空书名或空知识点：界面内校验，禁止创建；
- 损坏的本地数据：忽略并显示空书架，不影响知识点提取；
- 本地存储不可写：新书保留在内存中，并显示“本次可用，关闭后可能丢失”；
- 课程返回：始终回学习书架，不根据进入课程前的知识点页面推断返回目标。

## 验证

自动化测试覆盖：

- 课程按钮文案与返回目标；
- 默认书名和书名编辑；
- 上移、下移与移除；
- 空书名、空知识点禁用创建；
- 相同知识点连续创建不同 `bookId` 的学习书；
- 新书置顶与高亮；
- 本地存储往返、损坏数据与写入失败；
- 刷新后恢复学习书；
- 知识点、整理页、书架和具体学习的完整浏览器流程。

## 非目标

本轮不增加章节手动划分、拖拽排序、跨设备同步、SQLite 表、复习调度或真实掌握度写入。
